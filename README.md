# 研流 · yanflow

让AI和研究者一起推进项目，并让每次新对话知道：研究问题是什么、证据在哪里、什么已经完成、下一步怎样接续。

这是一个可复用的 Agent Skill，涵盖文献、作者结果复现、实验设计与执行、结果分析、头脑风暴、当前项目整理及交接。核心规则采用通用Markdown，辅助脚本使用Python标准库，面向支持Agent Skills的工具，并提供手动加载方式。

## 为什么做这个skill

长期用AI做科研，常见问题包括：实验越来越多却找不到主线；新对话重复安装或部署；代码、服务器结果和笔记对不上；项目完成了，研究者却无法解释关键机制。

本工作流同时记录三件事：

1. **工程状态**：代码是否实际运行、协议与版本是否对应、原始结果在哪里。
2. **研究证据**：哪个主张得到支持、哪些解释被排除、结论的范围是什么。
3. **理解与独立操作**：研究者实际解释或完成了什么，还需要哪些练习。

第三项受到 [How AI Impacts Skill Formation](https://arxiv.org/html/2601.20245v1) 的问题启发。该论文不构成本工作流有效性的验证；我们的学习机制仍需要实践检验。

## 安装

**默认选个人级安装，所有科研项目共用。** 项目级只用于有意随项目分发或固定版本的情形；同一工具保留一个实际使用的 yanflow 来源，避免个人、项目及账号副本重复扫描或使用不同规则。已有副本先保留本地修改再整合，不直接删除。

选你正在用的工具，复制对应的一条命令执行即可，需要已安装 Git。安装 skill 和建立科研项目是两件事，实际项目的位置由之后的对话决定。

**Codex**

```sh
git clone https://github.com/unno11/yanflow.git "$HOME/.agents/skills/yanflow"
```

**Claude Code**

```sh
git clone https://github.com/unno11/yanflow.git "$HOME/.claude/skills/yanflow"
```

`$HOME` 写法适用于 PowerShell 和常见 Unix shell；Windows 的命令提示符 cmd 请使用 PowerShell 执行这些命令。装完后让工具重新发现 skill，必要时打开新会话，再说“使用研流，帮我整理当前项目”或“开个新项目做……”。agent 会询问缺失的信息、定位目录并建立所需结构。

也可以直接把 [本仓库链接](https://github.com/unno11/yanflow) 交给具备安装能力的 agent，说“把研流安装到当前工具的个人 skill 目录”。它应检查现有安装后完成，不要求使用者手动复制文件。不使用 Git 时可下载仓库 ZIP，解压并保留完整 `yanflow/` 文件夹。各工具路径与官方依据见 [跨工具接入](references/portability.md)；同一工具避免重复安装同名副本，已有目录不覆盖。

### 安装后自查与更新

在新会话中先说“使用研流，读取这个项目的入口和交接”，确认它读取了 skill、项目入口以及映射到的主纲和现行交接。支持技能列表的工具可同时检查列表；例如 Claude Code 可用 `/skills` 查看，其他产品以其界面为准。agent 无权读取个人目录或账号状态时，应说明“安装／加载待核实”及失败原因，请使用者完成自查，不声称成功。

更新后在当前会话重新调用，并确认读取的是新版本；无法确认就开新会话再试。在项目主纲或交接记录使用来源、上游提交／可核实版本、本地修改状态及记录核对时间。只补新规则影响的记录，不重做整理或重跑实验。具体步骤与用户自查入口见 [跨工具接入](references/portability.md)。

### 不支持原生skill的工具

提供 `SKILL.md`，并让工具按任务读取相关 `references/`。如果它无法访问文件或执行脚本，只能使用文字流程，不能把建议当成已经执行。

## 怎么用

安装并让工具加载本 skill 后，直接用自己的话描述目的即可。支持自动发现的工具可按任务匹配；未自动加载时，选择它或说一次“使用研流（yanflow）”。下面只是简短示例，不是固定口令，无需每次复述目录、文献偏好或授权规则：

> 帮我找世界模型与潜空间规划的论文。

> 我们复现一下这篇论文。

> 接着这个项目做。

> 帮我整理一下当前项目。

> 这些论文读完、复现也做了，我们一起想想能做什么。

默认文献范围、归档要求、作者核心结果复现、项目结构及讨论边界由 skill 提供。缺少文献库位置等必要信息时才询问；用户本次提出的具体要求优先。可以组合任务，也可以只做其中一项，不强制从选题开始。自动发现取决于工具的加载机制，不能保证所有新对话都会自动找到项目。

## 默认文献与复现约定

- 近五年采用检索当年及前四个自然年，截止实际检索日；必要经典单列。
- 顶刊顶会优先，其他直接相关工作和预印本也可收录，分别核验发表状态。
- 本批候选全部初筛，重点论文全文精读并写中文笔记。下载状态和阅读阶段分开。
- 每篇保存PDF及真实 `.tex` 源文件和相关材料。没有公开LaTeX就标为部分归档，不制造空目录或假源码。
- 统一文献库与各科研项目单独维护，项目内通过索引引用，不反复复制文件。
- 复现默认针对作者核心结果；冒烟通过只是中间步骤。作者权重复核与从头重训分别报告。

## 项目结构

主体结构参考 [skJack/research-workflow](https://github.com/skJack/research-workflow)。以下是新项目默认结构；已有项目的每一项都可映射到已有位置或段落，不要求完整重建。统一文献库是有文献归档任务时的可选部分。

```text
统一文献库/
├── index.md
└── papers/
    └── 年份_短标题_稳定标识/
        ├── paper.pdf
        ├── source/                 # 真实.tex及作者提供的相关材料
        ├── record.md
        └── reading.md              # 重点精读时创建

独立科研项目/
├── AGENTS.md                       # 总纲、当前主线、路径与约定
├── handoff.md                      # 当前交接
├── brainstorm.md                   # 想法、反证和决策
├── related_work/index.md           # 本项目文献索引
├── 复现/
├── experiment/
│   ├── results.md                  # 实验和证据总表
│   └── evaluation.md               # 版本化评测
├── DataSet/
├── dataset.md
└── learning.md                     # 理解证据与独立操作
```

用户要求整理项目后，skill 会以职责为参考，在主纲维护实际位置映射。已有 `experiments/`、复现记录或学习段落时优先复用，出现近似目录请使用者选择，不再建一套。主纲可在 Obsidian 等项目外位置，仓库的 `AGENTS.md` 只作入口并可保留必要硬约束摘要；不复制动态主线。大数据与原始轨迹可以留在服务器，但索引需说明主机、路径及可访问工具。涉及移动或覆盖已有材料，先讨论具体方案。

若希望 agent、Git 和笔记软件读取同一套文件，推荐把主纲、交接等真文件放在仓库 `notes/`，根入口指向它们，笔记库通过目录链接查看。方向是“仓库内真文件，笔记库内链接”；Windows 命令、运行环境限制及迁移检查见 [记录位置方案](references/portability.md#仓库真文件与笔记库链接)。这是一种可选布局，外部主纲仍可沿用，第三方仓库是否纳入研究记录按项目约定决定。

## 让 agent 建立项目

直接对话即可，例如：

> 使用者：开个新项目，研究世界模型规划。
>
> agent：项目想放在哪里？
>
> 使用者：项目放 D 盘 Project 下。
>
> agent：我先检查 `D:\Project`，再补齐项目名称等缺失信息，建立项目骨架。文献库暂不建立，有文献归档任务时再确定。

agent 根据当前系统解析位置，在指定父目录内查找。路径唯一且意思明确时直接采用；有多个候选、目录不存在或“Project 下”尚未指定具体项目时，只问必要的选择。不扫描整块磁盘，不把示例路径当默认值；已有项目先识别和复用已有记录。使用者无需知道脚本参数，具体定位规则见 [项目建立与路径解析](references/project-records.md#自然语言定位与建立)。

<details>
<summary>手动初始化／供 agent 调用的脚本</summary>

需要 Python 3.10+，没有额外包依赖。agent 将对话中确定的位置转换成参数并执行；以下也可供希望手动操作的人使用：

```sh
# 在本仓库目录中，只建立统一文献库
python scripts/init_project.py --library-dir "文献库的实际位置"

# 只建项目，不要求文献库
python scripts/init_project.py --project-dir "项目的实际位置" --name "项目名" --goal "一句话研究目标"

# 同时补齐一个独立科研项目
python scripts/init_project.py --library-dir "文献库的实际位置" --project-dir "项目的实际位置" --name "项目名" --goal "一句话研究目标"

# 只补AGENTS及所需工具入口，不建其他目录；参数可重复
python scripts/init_project.py --project-dir "已有项目位置" --entrypoints-only --entrypoint claude --entrypoint gemini

# 主纲和交接在项目外；文件须已存在且当前可访问
python scripts/init_project.py --project-dir "已有项目位置" --entrypoints-only --entrypoint claude --main-record "笔记库中的主纲.md" --handoff-record "笔记库中的交接.md" --maintainer "负责会话" --constraint "已有的不推送约束"
```

某些系统命令名为 `python3`。脚本只创建缺失文件，保留已有内容；`kept-existing` 不表示已有入口已更新，agent 需要读取后局部接入。Git 可用时报告忽略状态，被忽略的入口标为 `ignored-local-only`，不自动改忽略规则、提交或推送。第三方仓库／fork 中记录放哪里、是否入库按用户约定处理。近似目录仅做常见别名检查，复杂映射由 agent 维护。

脚本负责建立文件，不自行检索论文、训练模型、安装工具或启动服务器实验。已有定时检查与自动接续需要写入交接；共享记录改写前核查负责会话、保留必要历史，并记录写入者和核验时间。具体见 [项目记录](references/project-records.md) 与 [跨工具接入](references/portability.md)。

</details>

## 内置科研警示

**仅在已加载 yanflow 的对话里，由 agent 遇到相关现象时检查；新对话建议先说“使用研流”。** 无需另行输入警示名称。这是行为指引，不是后台监控或保证不会遗漏的硬性拦截，也不要求每次任务填写整张检查表：

- **效果突然变好**：先核查数据泄漏、样本身份、部署信息和评测口径，再解释方法收益。
- **代码看起来正确**：仍要追踪实际输入、中间产物和输出，核对预处理、单位、掩码及权重加载。
- **准备继续或重启实验**：先查实际进程、已有结果、恢复点与自动接续队列，避免重复运行。
- **本地代码已经修好**：核实服务器实际执行版本，历史结果仍绑定当时的代码和配置。
- **结果不理想**：保留失败版本；不临时换指标、筛样本、加预算或只报告有利种子。
- **反复报同一个错**：停止没有新证据的同类重试，提出可验证的诊断；方案变化先讨论。
- **准备宣称创新或机制成立**：核查最近邻文献、强基线、同预算对照和反证，候选 idea 不写成已验证结论。
- **上下文变长或阶段有进展**：及时更新交接；记录已做、不可直接重跑的操作、核验时间和下一步。
- **审计越来越多，研究却没有推进**：检查只围绕当前判断，复用仍有效的通过证据，达到结束条件后回到已授权工作。
- **为了快速交付而缩减目标**：对照原定范围和完成标准，保留尚未完成部分；缩减范围或降低标准先共同决定。
- **少数失败就准备结束方法路线**：限定负结果实际否定的条件，保留未完成验证；按已有停止约定或共同讨论决定路线。
- **任务越做越多，研究逐渐偏移**：实质工作对应当前研究问题和关键证据，必要支线有结束条件及返回点；新 idea 先记录，调整主线先讨论，并保留反证。

完整触发条件与处理方式见 [科研警示与纠偏](references/research-guardrails.md)。新出现的问题按“现象—证据—根因—处理—适用范围”积累；项目特有问题留在项目记录，确认有通用价值后再更新 skill。

## 协作与学习

默认平衡推进：环境修复、既定运行和归档自主处理；核心假设、代码接口和结果解释留出共同思考。根据实际任务选少量预测、解释或独立操作机会，不反复考已经掌握的概念，也不以学习为由卡住无关的已授权工作。

阶段结果改变主线判断，或准备请求批准下一步研究方案时，随结果简报提出 1–2 个针对性理解问题，避免长期积压到“以后讨论”。使用者说“先不讨论”即可跳过，交接记录待回看项；不把回答测验作为实验授权的附加条件。

跨项目的语言、时区、汇报格式与沟通偏好放在使用者级说明或账号偏好中，接入时复用，项目主纲只维护项目特有约束。例如 Claude Code 的 `~/.claude/CLAUDE.md`；其他工具按其个人说明入口处理。详见 [使用者级偏好](references/portability.md#使用者级偏好)。

头脑风暴既可以在遇到瓶颈时开展，也可以在阅读一批文献、完成核心结果复现后开展，用证据综合形成新 idea。用户提出时直接进入；阶段复盘发现值得讨论的切入点时主动提出讨论。比较主线改进和方向选择，给出依据、反证与最小验证方案。支持子agent且授权允许时可以委派；不支持时由当前对话完成并说明。提出方案不等于执行授权。

新增实验、改变协议、增加预算或调整方向先共同讨论。交接中记录已完成操作、现有自动接续队列、最近核验时间及不可直接重复的原因。

## 仓库内容

- `SKILL.md`：触发范围、共同规则和按需阅读入口。
- `references/`：各任务的详细指导。
- `assets/templates/`：可复制的空模板，不包含私人项目记录。
- `scripts/`：可移植辅助脚本。
- `agents/openai.yaml`：可选界面元数据，其他工具不依赖它。
- `tests/`：初始化及已有文件保护的行为检查。

运行本地检查：

```sh
python scripts/check_skill.py
python -B -m unittest discover -s tests -v
```

## 当前验证范围

已通过11项本地测试，覆盖中文路径、重复调用保留原文件、只建项目、只建库、只补入口、外部主纲与约束摘要、近似目录冲突、忽略状态和实际命令行。测试数据使用系统临时目录，`-B` 避免生成安装目录中的Python缓存；受限环境可为测试进程设置安装目录以外的可写 `TEMP`／`TMPDIR`。

跨工具与云端安装、Obsidian内链规则已按官方文档核对，未逐个产品实测。`.skill` 扩展名本身不代表账号持久化，须按对应产品要求上传并启用；目录存在也不代表 skill 已加载。真实论文获取、并发协作、长期理解及警示效果仍需实际使用验证。
