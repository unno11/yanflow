# 文献检索与归档

## 用户已确认的目标

关注近五年的领域论文，加少量对理解问题或方法必要的经典论文；优先顶刊和顶会。其他相关期刊、会议和未正式发表的预印本均可收录，分别注明发表状态，不把预印本称作已接收论文。均可收录不等于承诺穷尽所有文献。

采用统一文献库，各科研项目单独维护。交付包含可获取的论文 PDF、LaTeX 源码及专门存放它们的文件夹；只给对话中的链接不算完成该类归档任务。

本说明用于实际文献任务。设计 skill 时用户回答文献偏好，只更新规则，不据此启动实际研究或批量下载。

## 确定检索范围

从当前项目和用户请求识别领域，复用项目已有的文献范围。年份默认采用检索当年及前四个自然年，截止到实际检索日，并在索引中注明；用户指定其他窗口时按其要求。经典论文单列，并说明为何超出年份窗口仍选入。

先检索顶刊顶会的相关工作，再补充重要预印本及其他相关论文，不因发表场所较低而遗漏直接相关的方法或反证。领域不同采用相应的期刊／会议范围；具体等级标准不清楚且影响筛选时才问用户，不反复询问已确定的通用偏好。

首次建库时，向使用者询问统一文献库的建立位置；已有明确位置时直接复用。项目位置分别确认，不把文献库存进某个项目以充当全局库。实际位置写入文献库索引和项目记录，不依赖当前聊天记忆，也不擅自修改个人工具配置。

接受自然语言位置，agent 自行在指定父目录核查并建立，不要求使用者填写脚本参数；歧义与不存在路径按 [自然语言定位与建立](project-records.md#自然语言定位与建立) 处理。

实际检索时通过出版社或期刊官方页面核验期刊、发表状态及时间。若使用分区、等级或某年的名单作筛选依据，注明体系和年份；未核验时不声称符合该等级。

## 检索、核验与筛选

围绕领域术语及相邻标准术语搜索，优先使用期刊、出版社、作者主页和官方论文仓库。记录检索范围、日期和关键词；不把没有搜到当成没有相关工作。

核实每篇论文的标题、作者、期刊、正式发表／在线发表时间、DOI 和可对应的预印本标识。发表版本和预印本可能年份不同、内容不同，分别标明，不把 arXiv 出现当成正式接收。

筛选依据为：符合近五年窗口或经典例外，且与当前领域或问题实质相关；顶刊顶会优先。按问题或机制归类，说明选入原因；用户需要领域概览时，不把检索过早收窄为当前单一实验方案。

论文总量依请求确定，不预设固定篇数。默认先对本批候选全部初筛，再对重点论文全文精读。不因下载方便而用低相关预印本替代符合范围的论文；未获取的条目仍保留来源与状态。

## 分层阅读：全部初筛，重点精读

“全部初筛”指对本次检索获得的候选逐一筛选，不是承诺搜尽领域内所有论文。初筛核对标题、摘要、发表信息及必要的图表，记录问题、主要思路、相关性与保留／排除原因。只读摘要的判断明确标明，不能写成全文结论。

优先精读与当前问题直接相关、构成强基线或最近邻、影响创新性判断、提供关键机制／反证，或用户指定的论文；顶刊顶会优先，但不因此跳过直接相关的预印本或负结果。结合当前用途给出优先级和理由，不把每篇收录文献都默认升级为精读，也不固定篇数。

精读核对全文的方法、关键假设、公式、实验设置、主要结果、对照、局限和适用条件；需要时对照LaTeX与作者代码。下载完成不等于读完，精读完成也不等于复现完成。全文缺失时保留“精读待完成”，不要用摘要补写未核实细节。

阅读阶段在库索引中标明，例如“待初筛”“已初筛”“待精读”“已全文精读”，另记PDF／LaTeX获取状态和待核实事项。已初筛的论文可进入重点队列；初筛时排除的条目记录理由即可，不强制下载全部排除项。

重点论文在论文目录中保存 `reading.md`，可采用 [精读笔记模板](../assets/templates/reading-note.md)。通用论文解读保存在共享库；与某个项目的关系、可借鉴点和待讨论实验保存在该项目 `related_work/index.md`，避免项目推断被当成论文原结论。用户明确希望改变本次阅读深度时按其请求。

## 文件夹组织

沿用使用者指定的统一文献库；没有时先询问建立位置，再创建。共享库与项目 `related_work/` 的对应如下，名称按项目习惯调整：

```text
统一文献库/
  index.md
  papers/
    年份_短标题_稳定标识/
      paper.pdf
      record.md
      reading.md              # 仅重点精读论文创建
      source-original.tar.gz
      source/
        实际主文件名.tex
        章节文件.tex
        references.bib
        figures/

独立科研项目/
  related_work/
    index.md                  # 指向统一库；记录本项目用途与阅读笔记
```

`source-original.tar.gz` 仅表示原始源码包的一个例子；实际文件名和扩展名按下载格式保留。来源直接提供 `.tex` 或其他格式时据实记录。源码不存在时不创建空源码包或空 `source/` 来表示成功。

**每篇论文的LaTeX是明确交付项。** `source/` 必须包含实际 `.tex` 文件，不能只建一个空目录，也不能只有未解包的源码压缩包。保留作者主文件名、章节、参考文献及图片等相对关系；主文件不一定叫 `main.tex`。只拿到PDF而未拿到LaTeX时，将该条目标为“部分归档／源码缺失”，继续查找公开来源并如实报告。

上面的章节、`.bib` 和图片目录是常见示例，按实际源码保存，不制造缺失文件。源码的存在与是否能完整编译分别判断。

使用 DOI、arXiv 标识或其他稳定标识去重，避免仅因标题写法不同重复下载。同一论文的出版社版本与预印本放在同一论文目录内，文件名区分版本；确需保留不同版本时不相互覆盖。

`index.md` 集中记录标题、期刊／年份、所属主题、初筛判断／精读优先级、阅读阶段、PDF 状态、源码状态和论文目录链接。可按多个主题引用同一论文目录，不复制成多份。

`record.md` 保存论文身份、版本、来源链接、下载日期、获取状态和简要相关性说明。PDF 与源码来自不同版本时明确披露；不要暗示出版社 PDF 与预印本源码完全一致。

## 下载 PDF 与 LaTeX

1. PDF 优先取期刊或作者提供的公开正式版本；只有预印本可获取时，记录该版本。核对标题或标识，并确认取得的是有效 PDF，而非登录页、错误页或仅名为 `.pdf` 的 HTML。
2. 源码优先从作者公开仓库、论文官方材料或对应 arXiv 版本获取。确认文件中确有 LaTeX 内容；源码接口返回 PDF 或错误页不能算获取成功。
3. 保存原始下载件及来源。在论文专属目录内解包，检查归档成员路径，避免覆盖目录外材料。原始源码不做破坏性清洗；确有阅读需求时在单独副本中整理。
4. 只做归档时无需编译论文或执行源码仓库中的脚本。下载后核对文件类型、大小和必要校验标识，记录缺失的图片、参考文献或主文件等影响源码完整性的情况。
5. 遇到失败，仅重试相关文件；已有有效文件不重复下载。下载版本更新时保留身份及版本对应关系，不静默覆盖旧版本。

并非所有期刊论文公开 LaTeX。找不到公开源码时，状态写为“未找到公开源码”；需要额外账户权限则注明；明确未提供、下载失败和仍待核实分开记录。不要从 PDF 反生成 `.tex` 冒充原始源码，不创建来源不明的成功记录。

## 交付与继续工作

交付专用目录和可点击索引，分别核对每篇PDF、`.tex`及相关材料，简述筛选范围、初筛及收录数量、重点精读清单及理由、PDF／LaTeX均齐备数量和部分归档缺项。论文解读区分摘要阅读、全文核对和推断；只归档而未精读时如实说明。

将文献索引位置写入项目入口或交接，使下一次文献任务先查现有库再补充。在项目 `related_work/index.md` 中保留与本项目有关的索引及笔记，不复制整套 PDF 和源码；不同项目可有不同领域范围。跨项目共同使用同一论文时复用库内文件。

实际精读、提出研究 idea、复现和新实验是后续不同任务。文献发现可记为待讨论启发，不自动改变项目主线或启动实验。
