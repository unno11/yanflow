# 项目记录与交接

## 先确定各类记录的位置

优先检查已有项目说明、handoff、实验总表与笔记。维护一份轻量索引，指向每一类记录的主要维护位置，不另造平行版本。项目有多条活跃路线时分别标出负责人或对话、当前状态及交接入口。

新项目的主要目录结构参考 [skJack/research-workflow](https://github.com/skJack/research-workflow)，采用以下骨架。统一文献库是用户选择的扩展，各项目单独建目录；已有项目先映射现有文件职责，不为统一名称迁移正在使用的文件。

```text
科研项目/
  AGENTS.md                   # 项目总纲、主线、路径与协作约定
  handoff.md                  # 当前进度与接续条件
  brainstorm.md               # 问题、假设、候选idea与决策记录
  related_work/index.md       # 本项目文献索引，指向统一库
  复现/                       # 各方法的复现材料及报告
  experiment/
    results.md                # 实验总表与证据对应
    evaluation.md             # 版本化评测协议
  DataSet/                    # 本项目数据；大数据可仅保存位置索引
  dataset.md                  # 来源、划分、处理与数据版本
  learning.md                 # 少量理解证据与独立操作记录
```

统一文献库采用 `index.md` 和 `papers/<论文标识>/paper.pdf + source/`，详见 [文献归档](literature.md)。需要时才在项目中增加详细协议、运行清单或学习记录，不默认增加另一套平行主纲。路径用项目内相对路径或带主机标识的完整位置。

本次涉及文献归档且需要建库时才询问统一库位置；只建项目或补入口时不询问、不建立，可记为“可选，未建立”。创建新项目补齐位置、名称与目标等必要信息，已有答案直接复用。脚本支持只建项目、只建库与仅补入口；已有主纲需要补充路径时先读再局部修改，不整体替换。

## 已有位置与外部主纲

骨架中每一项都允许映射到已有文件、目录或文档段落，包括 `learning.md`、`复现/` 和评测记录。在主要维护的主纲中列出“职责／默认名称—实际位置—维护者—可访问工具—核验时间”；不为了填满表格创建没有用途的实体文件。

主纲在 Obsidian 等项目外位置时继续复用。仓库内的 `AGENTS.md` 只提供主机标识、绝对位置、负责维护者及读取方式，允许必要硬约束摘要并注明“完整版见主纲”、来源与核验时间；它不另行维护当前主线。外部主纲不可访问时如实标记，保留已知限制，仅暂停依赖缺失信息的工作。

如需方便 agent 访问并保存 Git 历史，可选择把主纲、交接与其他项目记录的真文件放在仓库 `notes/`，根入口只指向它们，Obsidian 等笔记库通过目录链接查看。保持“项目内真文件、笔记库内链接”，不创建两份独立演化的主线；既有文件名和数量不必更换。迁移前保留旧记录和历史、核查负责会话，并按项目约定确认是否入库。Windows 命令、链接方向与跨环境核验见 [仓库真文件与笔记库链接](portability.md#仓库真文件与笔记库链接)。

使用者级的语言、时区与汇报偏好只在项目中记录来源和可用性，复用工具个人说明或账号偏好；主纲保留本项目的权限、预算、路径及研究约定，见 [使用者级偏好](portability.md#使用者级偏好)。

发现 `experiment/` 与已有 `experiments/` 等近似名称时，先说明拟映射及位置，让使用者选择在原目录补索引、只映射或采用另一个明确位置；已有选择可直接复用。默认不新建近似名目录。初始化脚本会拦下部分常见别名，无法识别所有语义等价关系；复杂映射由 agent 在既有记录中维护，或使用仅补入口模式。

## 自然语言定位与建立

由 agent 问缺失信息、查找目录并调用脚本。使用者可回答“D 盘 Project 下”“当前仓库里”或“沿用现有文献库”，不要求其提供完整命令或填写固定问卷。

1. 从当前项目约定、工作区和对话复用已知位置，区分科研项目、代码库、笔记与可选文献库的职责。仅在本次需要文献库时解析“沿用现有库”，先查已有索引，找不到时再问；项目接入不以确定文献库为前提。
2. 按实际操作系统解析路径。在 Windows，“D 盘 Project 下”首先检查 `D:\Project`；在其他系统或目标是服务器时，确认该位置实际存在于哪台主机，不把它默认为当前机器路径。
3. 先检查明确路径和必要的一层子目录。精确路径不存在时，可在用户指定的父目录查看少量相近名称；不递归扫描全盘、其他主机、模型缓存或私人目录。唯一且明确的匹配可直接采用，多个合理候选用简短选择题澄清。
4. 区分新建与接入：新建项目在父目录下建立一个有意义的项目子目录；名称从已给信息提取，无法确定时才问。整理已有项目时检查候选目录的说明、总纲或代码入口，在项目根目录或既定笔记位置建立索引，不再套一层项目副本。目标路径不存在且创建意图不明确时，问“新建这个目录还是使用现有位置”。
5. 执行前用一句话说明解析后的完整位置和本次建立内容；已有授权且目标唯一时直接执行，无需再等一次确认。权限或工具限制如实说明，仅对需要的访问请求授权，不把找到目录误称为拥有写权限。
6. agent 将解析后的绝对路径转换成初始化参数。脚本路径以 skill 实际安装目录为准；项目名、目标等已知内容写入模板，未核实项标注待补。若已有成熟结构，直接维护对应记录，不为使用脚本强建第二套文件。
7. 完成后核查实际文件、主要入口和文献库引用，将最终位置写入项目总纲与交接。报告新增与复用的内容；不把建议命令、空模板或工具成功返回等同于完整项目整理。

仅在本次任务确实需要建立项目或文献库时执行这些步骤。安装 skill 只部署规则与资源，不自动在默认磁盘上创建研究项目。

| 记录职责 | 最少内容 |
| --- | --- |
| 项目索引与当前主线 | 项目根目录和别名、研究问题、候选创新、当前主张、最新支持及反证、阶段和待决策事项、其余记录位置 |
| 实验索引 | 稳定实验标识、假设、协议、状态、实际执行版本、结果和证据位置 |
| 当前交接 | 最近更新时间与核验时间、已完成操作、运行中任务、不可重复操作、下一步和待决定事项 |
| 理解记录 | 用户实际解释或操作的证据、需要补充的部分、下次可讨论的问题 |

新项目默认主纲在 `AGENTS.md`，交接在 `handoff.md`，其余对应骨架；已有项目以映射表为准，外部主纲时 `AGENTS.md` 只作入口。学习、复现与其他每类职责都可复用已有记录，不强制增加文件。

不同工具共用同一套项目记录；有需要才补指向主纲的短入口，见 [跨工具接入](portability.md)。不要复制一份工具专属主线或交接，再让它们各自演化。

若只有一两个实验，允许合并为单一文档的不同段落。沿用项目既有的 Obsidian 或其他笔记位置；不能访问时明确哪些内容尚未同步。

## 实验对应关系

一条实验记录根据实际需要包含：

```yaml
experiment_id: 项目现有的稳定编号或描述性标识
hypothesis: 正在检验的具体主张
status: planned / running / completed / stopped / invalid
protocol: 协议文件和版本；执行授权的来源
execution: 实际运行的代码提交或源文件标识；工作区差异；配置
inputs: 数据版本与划分；权重标识；种子或种子映射
runtime: 主机；运行目录；作业或进程标识；启动及最近核验时间
evidence: 原始结果；日志；分析文件；本地归档；笔记链接
conclusion: 主要结果、证据范围、未解决的问题
```

上述是字段说明，按需记录实际值，不复制说明文本冒充已知事实。原始数据较大时记录位置和已有校验标识，不要求复制进 Git。缺少哈希或代码版本时标明缺项，不为了补字段无差别计算所有大型文件。

实际执行版本和之后的代码修复分别记录。待运行方案不写成已执行；命令已提交不等于任务已完成；完成状态应关联日志、退出状态或结果文件等可核实证据。

一个项目同时训练、编排后续队列和分析旧结果时，分别记录各自执行位置与版本；本地 HEAD 不自动代表任何已部署任务。某阶段完成或某个论断被撤回后，核查当前入口仍引用的摘要是否滞后，并标明更正去向。历史报告不覆盖，当前读者应能明确找到现行状态。

整理产生的清单、快照与核验记录优先放在项目所用工具能访问的持久位置，并从主纲或交接引用。确需放在项目外时记录主机标识、完整路径、生成时间、包含的内容、已核实可访问的工具／会话和未验证者；个人聊天工作区或临时目录不能充当默认的共享证据库。换工具后重新核实访问，无法访问时写明哪些结论暂不能复核，不把路径存在当作访问成功。外部位置的链接形式见 [跨工具接入](portability.md)。

## 当前交接的建议骨架

主纲或交接还应记录研流实际使用的来源与安装方式、上游提交／可核实版本、本地修改状态、本会话是否已重新加载，以及记录按该版本核对的时间。文件更新、会话加载和记录迁移是不同状态；无法核验的项写待核实。skill 更新后只补相关规则缺项，保留现行主线和历史，不为追版本重做整理。

```markdown
# 当前交接
更新时间：含时区；当前项目：根目录与适用约定入口。

## 当前问题与阶段
研究问题、当前主张、目前可以支持的结论；链接主线记录。

## 已完成
任务或实验编号、已完成的关键操作、核验依据。

## 运行中
任务标识、运行位置、最后核验时间、如何只读检查状态。

## 已有定时检查与自动接续
编排标识、主机／工具、状态、触发时间及时区或依赖条件、目标会话／任务、负责人、最后核验时间；接续前实际核查，不能重复建立。

## 不可直接重复的操作
具体操作、已完成证据、重跑风险，以及何种条件下才可恢复或重试。

## 下一步
已经授权的具体步骤；开始前需要检查的条件；待讨论事项。

## 证据与理解
关键结果及代码入口；用户已解释的内容和下一次需要讲解的部分。
```

保持当前交接简洁，更新前保留有价值的旧状态，按当前交接所在位置处理：

- 旧内容已由 Git 等版本控制保存且可定位时，记下实际提交与文件路径；未提交、被忽略或仅本地的文件不能据此假定有备份。不为保存交接擅自提交到第三方仓库或推送。
- 没有可用版本历史时，默认在当前交接旁的 `handoff-history/` 保存 `YYYYMMDDTHHMMSS_时区_简述.md` 快照，包含来源、写入者和时间；小项目也可保留文件末尾按时间倒序的历史段。已有 `_历史快照/` 等约定直接复用，不再建平行历史目录。
- 新交接留实际历史入口。保存失败时停止覆盖对应旧状态，先解决存放或权限问题。完成说明替代顶部仍显示“运行中”的摘要，原始事件和结果保留。

已有定时检查与自动接续必须区分“历史记录存在”和“已核验仍有效”。记录会唤醒哪个会话、是否仍绑定原工具以及跨会话能否操作；无权核查则标未核实并与负责人协调，不默认重建或迁移。记录这些信息不构成新建自动任务的授权。

不保证新聊天自动发现项目，项目入口应能明确指向本交接。

## 多工具与多会话写入

共享可变记录在文件头维护最后写入者（工具／会话标识）、含时区的更新时间，以及相关事实的最后核验时间；文档写入时间与服务器状态核验时间分开。接入时查看已有负责会话与进行中操作；无法确认时先只读并将拟改内容写入独立建议，不能把对方暂未更新当作无人负责。

写入前重读受影响段落或检查此前读取的版本／摘要是否变化；若有其他会话正在维护同一段，先协调单一写入者，或约定互不重叠的文件。无法直接联系时请用户协调，独立已授权工作可以继续。发生并发变化时合并差异并保留对方更新，不用旧全文覆盖。文件头信息只是追溯线索，不是锁，也不能证明没有其他写入方；不为此引入永久锁、全项目扫描或停止所有研究。

## 记录冲突

遇到笔记、交接和原始记录不一致，记录冲突与来源时间，核查相关运行记录和实际版本。不能靠文档日期或“权威”标题自动选定结论；未解决时明确列为待核实。更正分析保留原报告和更正原因，项目索引指向当前采用的版本。
