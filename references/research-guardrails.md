# 科研警示与纠偏

这是按现象触发的检查，不是每项任务都要完成的审计表。普通问题在授权范围内自主纠正；涉及新增实验、协议、预算或方向变化时准备具体提案共同决定。暂停受影响的运行、比较或结论，继续独立且已授权的工作。

## 自动触发的含义

本 skill 被加载后，由执行任务的 agent 识别相关现象，按需读取本文件并开展对应检查，不要求使用者额外输入警示名称。它是任务内的行为指引，不是后台监控、定时任务或工具层强制拦截；没有实际检查就不能声称已排除风险。没有相关信号时直接推进当前任务，不为了触发警示主动寻找无关问题。

## 检查应帮助研究推进

- 每项额外检查应对应一个具体待判断问题，说明它可能影响哪个运行或结论，以及何种证据足以结束检查。优先复用已有记录和最小必要验证；检查规模随实际风险和当前任务变化，不追求排除一切可能性。
- 相关检查已通过且代码、数据、协议和运行身份没有影响该判断的变化时，复用结论。只有新失败、新证据或相关变更才重开，不在代码审计、文件整理与文档核对之间反复循环。
- 推测性担忧记作待核实，不凭担忧否定方法、强制新增对照或暂停整个项目。确认的问题按影响范围处理；真实数据污染、结果无效或既定停止条件成立时，暂停相应工作并如实报告，不为追求推进继续产出无效证据。
- 已约定的研究问题、方法目标、核心实验和完成标准保留在项目总纲及实验协议。小规模诊断与最小验证用于阶段反馈；agent 不能为了省事、快速交付或回避不确定性，擅自把核心结果复现降为跑通、删去困难条件、压缩研究问题，或把部分完成报告为任务完成。
- 对结论按证据限定，同时保持约定的任务目标。一次实现失败、局部负结果或证据尚不充分，分别记录其具体条件及影响；是否收窄、放弃或结束整条方法路线，应依据已有决策约定或与用户讨论。已有明确停止条件可直接执行，但一次运行停止不自动意味着整条路线结束。
- 建议结束或改变路线时，给出支持与反对证据、尚未覆盖的解释、原计划完成情况，以及继续验证／修改／结束各方案的资源和判断条件。信息不足时明确“当前尚不能判断”，保留有依据的负结论，不制造必须成功或必须放弃的倾向。

## 触发与处理

| 风险信号 | 应做的检查与处理 | 恢复推进的依据 |
| --- | --- | --- |
| 指标突然提升，或测试好得不合常理 | 查训练／验证／测试的真实样本身份和分组单位、重复样本、预处理拟合范围、未来信息与特权输入；核查指标实现和样本筛选变化。相关时查看历史样本暴露记录 | 提升来源可追溯；发现污染则标记受影响结果，修正方案共同决定，不能直接宣称方法有效 |
| 代码审查通过，但实际行为异常 | 在已授权检查内追踪一条真实输入到输出，核对张量、预处理、掩码、单位、归一化、权重是否确实加载、缓存是否对应本次配置；需要额外实验时先提案 | 有实际中间产物和预期行为的对应证据，不能只写“看起来没问题” |
| 本地修好了，服务器结果却不变 | 核查实际进程、工作目录、部署代码、配置、数据与权重身份；区分当前修复和已产出结果所用版本 | 运行身份与结果索引对应；不能用当前本地 HEAD 替代历史执行版本 |
| 新对话想“接着跑”或重启任务 | 先读交接，再查已有进程／作业、输出、检查点与编排；核查定时检查的标识、状态、触发时间及时区、会唤醒的会话／任务与负责人，以及自动接续依赖；旧时间戳不代表现在仍有效 | 明确恢复、等待或重试条件，不重建已有定时任务或开第二套运行；无权核验时与负责人协调，不覆盖现有结果 |
| 同一错误反复出现，却没有新诊断 | 停止同类盲目重试，保留最小失败证据，区分环境、接口、实现和研究假设；每次尝试说明检验哪个判断及停止条件 | 新尝试有可区分原因的证据目的，且仍在既定方案和预算内；改变实验语义则先讨论 |
| 指标不理想，开始换样本、种子、指标或预算 | 对照 `experiment/evaluation.md` 的现行版本；保留完整尝试与失败，探索分析和确认分析分别标注，不能只报告最好一次 | 采用原协议完整报告，或经讨论形成新版本；偏离与对应结果明确记录 |
| 新方法赢了，但对照条件不同 | 核对数据、初始化、训练／推理预算、搜索与规划调用、调参机会、权重来源；报告额外计算和资源差异 | 比较在主张要求的条件下成立，或明确限制结论；补充对照属于新实验时先讨论 |
| 损失下降、oracle 或单一诊断改善，就宣布机制成立 | 区分工程成功、代理指标、真实任务收益与因果机制；列出仍成立的替代解释及反证，结合跨种子或样本波动给出适当不确定性 | 结论强度与现有证据匹配；新增消融、重跑或确认实验先共同决定 |
| idea 听起来新，或论文标题像是支持主张 | 核查最近邻原文、发表状态和证据位置；摘要阅读与全文阅读、论文报告与本地复现、下载成功与阅读完成分别记录 | 未核实的新颖性和解释保持候选状态，引用能定位到实际来源，不把搜索不到当作不存在 |
| 文件越来越整齐，研究主线反而更难找 | 回到研究问题、当前主张和支持／反证，建立实验—代码—协议—原始证据—结论的映射；优先更新已有主要记录 | 当前入口能找到主线及证据；不为外观迁移活跃目录，不复制平行总纲 |
| 上下文变长、阶段结束或出现重要决策 | 当时更新 `handoff.md`：已完成、运行中及核验时间、不可直接重复的操作、下一步与待决定项 | 新对话可据文件恢复，并能区分已核验事实、历史状态和待核实项，不依赖聊天记忆 |
| agent 已交付，使用者却无法解释核心结论 | 区分交付、科学证据与理解状态；按 [学习与独立判断](learning-and-ownership.md) 选择必要的解释、预测或独立操作机会 | 根据用户实际表现记录理解，不以“继续”认定掌握，也不以测验阻断无关已授权任务 |
| 检查越来越多，已通过的问题反复被审计 | 回到当前待决定事项，逐项确认检查是否会改变判断；复用仍适用的通过证据，移出无关审计，给必要检查明确结束条件 | 有限检查足以支持当前步骤后恢复已授权研究，不把“所有风险都排除”当作开工前提 |
| 为了尽快交付，研究范围或验收标准悄悄缩小 | 对照项目总纲和原协议，列出承诺完成、实际完成和仍缺的部分；区分阶段验证与最终交付 | 按原范围继续；确需缩减时提出具体影响并共同决定，不能靠改写目标宣布完成 |
| 少数负结果后就宣布“方法不可行”或结束路线 | 区分实现错误、某个设置不成立、机制反证和整条路线；核查负结果适用范围、预先约定停止条件及原计划未完成部分 | 如实给出限定结论和后续选项，执行已有停止约定或共同讨论路线决定，不私自扩大失败范围 |
| 工具、审计、文献或新 idea 不断增加，工作逐渐偏离主线 | 对照总纲中最新约定的问题、主张与下一项关键证据，判断当前任务的实际作用；必要支线写明目的、结束条件及返回的主线步骤，无关想法放入 `brainstorm.md` 待讨论 | 阶段产物能说明对主线判断的影响；完成必要支线后返回原任务，调整主线须按已有约定或共同决定 |

世界模型与具身项目还应在相关时检查时间粒度、动作语义、坐标与单位、oracle 可部署性，见 [领域专项](world-model-and-embodied.md)。

## 保持主线而不过早收敛

从总纲与最新决策读取主线，交接保留“当前问题／主张—下一项关键证据—正在处理的必要支线及返回点”。发现偏移时先停下未获授权的新扩展，保存已有结果，回到已授权主线；若返回主线依赖新实验或尚待决定的方案，先讨论对应部分。

探索阶段以约定的文献范围、开放问题和候选路线为依据，允许经授权的并行探索。独立文献请求按其实际范围完成，不为了贴合既有方法而过滤重要工作、反证或强行选题。证据削弱主线时如实记录并提出调整建议；主线变化保留旧决策、原因、用户决定及未完成任务的去向，不能靠改写总纲掩盖偏移。

## 用真实问题改进警示

发现值得保留的问题时，在项目现有记录中简记：**触发现象、证据入口、已确认根因或尚存假设、处理结果、适用范围与重开条件**。失败和负结果也保留，不把未定位问题写成已解决。

项目特有路径、参数、阈值或一次实现失败留在该项目，先形成有依据的候选经验。经核实有通用价值并得到维护者采用后，才提炼进本文件；不把一个项目的统计门槛或偶然现象强加给所有研究。实际调用 skill 不自动授权修改或发布公共仓库。
